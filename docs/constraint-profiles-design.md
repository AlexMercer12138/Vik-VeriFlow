# 原文约束与板卡接口 V1

本设计已获用户确认。板卡约束尚未出现在已发布 changelog 中，直接重构当前 V1；AD 文档原有版本保持不变。

## 数据

用户库仍保存 `{id, name, model}`。板卡和子卡的 model 只有：

```json
{
  "kind": "board",
  "extension": ".xdc",
  "constraints": "set_property PACKAGE_PIN A1 [get_ports tx]\nset_property PACKAGE_PIN A2 [get_ports rx]\n",
  "interfaces": [
    {
      "id": "UART0",
      "signals": [
        { "id": "tx", "direction": "output", "pins": ["A1"] },
        { "id": "rx", "direction": "input", "pins": ["A2"] }
      ]
    }
  ]
}
```

`kind` 为 `board` 或 `daughtercard`。原文只保存一次，引脚及其约束索引由导入器按需建立。接口直接属于板卡，不再使用独立接口模型、角色、Bank、供电、器件数据库或协议模板。`pins` 的顺序就是总线从高位到低位的匹配顺序，长度就是位宽；UI 可以编辑位宽并据此显示对应数量的引脚选择框。

工程继续保存 `board` 和逐位 `bindings`；子卡挂载只增加 `{id, board, connections:[{cardPin, boardPin}]}`。绑定来源可选 `card` 标识子卡挂载。无需新增装配文件或槽位模型。

## 文本处理

XDC 导入静态识别 PACKAGE_PIN/LOC、set_property -dict 及 get_ports 的字面量目标，建立原端口到引脚的索引。保留完整原文及命令顺序；渲染只替换明确识别的端口和子卡引脚，保留其余文本。共享多端口约束按实际绑定筛选目标。无法静态处理的动态目标给出明确诊断，原文仍可编辑和保存，不执行 Tcl。

其他格式使用显式 `{{PORT:A1}}` 和 `{{PIN:A1}}` 引脚锚点，前者替换为顶层端口，后者替换为最终物理引脚。用户直接维护模板原文和扩展名，无需新增厂商生成器。未选用引脚的命令不输出；注释和不关联引脚的公共约束保留。未改变任何绑定且全部端口参与时，原文往返一致。

子卡使用逻辑连接器引脚，挂载表把它们解析到主板实际引脚。子卡自己的约束原文负责该信号的完整输出，不额外叠加主板同一引脚的电气属性。两者文件扩展名必须相同，不进行格式转换。

## 入口与保护

共享核心处理模型校验、绑定、占用、总线、装配和原文渲染。运行时负责文件和用户配置的原子写入；CLI 和扩展调用同一用例。保留 AD 内嵌配置和 RTL `.pins.json` 保存入口。

板卡编辑器为“Import board → 编辑原文 → 新建接口和信号 → 设置方向、位宽并匹配引脚 → 保存”。导入对话框按支持的约束文件和 profile JSON 过滤。VS Code 与 `veriflow board ui` 共用同一 Web UI。工程面板为“选主板/挂载子卡 → 选接口并绑定端口 → 预览与导出”。删除供电、IO 标准和独立接口模板 UI。

输出扩展名来自主板；通用 `constraintsOutput` 用于覆盖输出位置。使用独立的生成归属记录保护人工文件，避免向任意格式原文插入标记。

## 未发布旧数据

旧板卡没有约束原文，不能伪造恢复。加载时明确提示重新导入约束；不维护旧厂商生成引擎。移除旧接口资源、示例和校验脚本的契约，以新的最小 V1 Schema 和板卡/子卡示例替代。
