# 约束工作台与独立板卡模板 V1

状态：用户已确认并实施。2026-11-01 根据用户最新意见重新设计模型与交互，替代此前约束文件导入、语法解析、子卡安装映射及主板位置/属性分段方案。

## 设计结论

1. 保留已经认可的工作台视觉：一个标签内切换 **Pin bindings / Board library**。
2. 只能新建板卡或导入板卡 JSON；**Import board** 文件选择器仅接受 `.json`。不导入 XDC、PCF 等约束文件，也不从字符串识别引脚或属性。
3. 用户自行填写输出后缀，手动添加资源名及其约束模板，再把一组资源组织为接口。主板资源名是逻辑标识，不要求再次填写封装引脚编号。
4. 主板固定接口的物理位置写在模板中，工程绑定只替换 `{signal name}`。
5. 子卡独立建模，模板支持 `{signal name}`、`{pin name}`；工程绑定直接填写实际 FPGA 引脚，使用子卡自己的全部约束。
6. 工程必须选择一个主板，子卡可选。删除子卡到主板资源的映射、安装槽位、位置转换和主板属性继承。
7. 按用户明确要求，不做主板和子卡之间的物理占用检查，不为此增加字段、输入步骤或提示。主板只建固定板载功能，排针/FMC 等外接功能由选用的子卡提供。
8. 保留 HDL 编辑器/资源管理器右键“添加约束”。当前文件直接成为工作台的目标，不要求创建或选择 AD 工程。AD 工具栏继续打开同一工作台。
9. 端口绑定以“从右侧端口列表拖到信号行”为主，取消逐行下拉端口选择。窄窗口仍保留端口列表。
10. 用户只填写名称，不填写板卡 ID 或子卡实例 ID；内部稳定标识自动生成，界面不展示 ID 输入框。

## 最小模型

板卡文件只有 id、name、kind、extension、pins、interfaces 这 6 个顶层字段。模型定义仍为 V1，不增加文件内版本字段。

```json
{
  "id": "carrier",
  "name": "Carrier board",
  "kind": "board",
  "extension": ".xdc",
  "pins": {
    "uart_tx": "set_property PACKAGE_PIN A1 [get_ports {{signal name}}]\nset_property IOSTANDARD LVCMOS33 [get_ports {{signal name}}]\n",
    "uart_rx": "set_property PACKAGE_PIN A2 [get_ports {{signal name}}]\nset_property IOSTANDARD LVCMOS33 [get_ports {{signal name}}]\n"
  },
  "interfaces": [
    {
      "id": "UART0",
      "signals": [
        { "id": "tx", "direction": "output", "pins": ["uart_tx"] },
        { "id": "rx", "direction": "input", "pins": ["uart_rx"] }
      ]
    }
  ]
}
```

| 字段 | 必要用途 |
| --- | --- |
| id | 程序自动生成的稳定标识，界面不要求填写 |
| name | 界面展示名称 |
| kind | board 或 daughtercard，决定可用占位符与工程绑定方式 |
| extension | 输出文件后缀，如 .xdc、.pcf 或用户自定后缀 |
| pins | 逻辑资源名到多行约束字符串的字典 |
| interfaces | 组织资源、信号与方向的本板接口列表 |

不保存厂商、器件、Bank、电平枚举、引脚数据库、原始约束文件、模板规则、默认物理位置或冗余位宽。

pins 的键例如 `uart_tx`、`led0`，由用户命名，用于 UI 引用和接口分组；不是封装引脚号。`A1` 已写在模板里，不另外存储，也不从模板里提取。

每个接口只有 id/signals；每个信号只有 id/direction/pins。方向相对 FPGA 顶层端口。列表长度就是位宽：例如 `pins: ["led7", "led6", "led5", "led4"]` 是 4 位信号。资源按逻辑高位到低位排列，绑定到 HDL 时按真实声明次序展开，不假定 HDL 索引是 3:0。

同一资源只存一份字符串。接口引用现有资源，不能复制模板正文；同一资源在实际工程中不能同时绑定多次。不同接口可以描述同一资源的不同用途，选用时检查重复逻辑资源即可，不推断字符串里的物理位置。

用户库内部可继续保留 `{id, name, model}` 结构，将 kind/extension/pins/interfaces 放在 model 内；对外板卡文件扁平保存 6 个字段。导入/导出只在身份与模型之间拆合，不重复存储数据、不增加第二套文件格式兼容分支。

## 子卡

子卡与主板使用相同形状，kind 为 daughtercard，资源模板可以使用位置占位符：

```json
{
  "id": "serial-card",
  "name": "Serial daughtercard",
  "kind": "daughtercard",
  "extension": ".xdc",
  "pins": {
    "tx": "set_property PACKAGE_PIN {pin name} [get_ports {{signal name}}]\nset_property IOSTANDARD LVCMOS18 [get_ports {{signal name}}]\n"
  },
  "interfaces": [
    {
      "id": "UART",
      "signals": [
        { "id": "tx", "direction": "output", "pins": ["tx"] }
      ]
    }
  ]
}
```

该子卡在工程中绑定 `sensor_tx` 并填写 `B7`，输出：

```text
set_property PACKAGE_PIN B7 [get_ports {sensor_tx}]
set_property IOSTANDARD LVCMOS18 [get_ports {sensor_tx}]
```

子卡资源名 tx 不需要映射成主板某个资源。它的 B7 是最终 FPGA 引脚；主板保存的 A1、LVCMOS33 不参与这个子卡信号的生成。

一个子卡可实例化多次，每个实例有独立的绑定和位置。只保存模型引用与自动生成的实例 ID，不新增安装、槽位或连接器对象。添加时只选子卡模型，无需填写实例 ID；UI 以板卡名称及自动序号区分，例如 Serial daughtercard、Serial daughtercard 2。

## 自动标识

板卡 ID 保留在存储中，解决重命名后工程引用仍需稳定的问题。新建时使用平台 UUID 生成器分配，不能从可修改的 Name 动态计算。编辑名称不会改变 ID，复制板卡生成新 ID，导出/重新导入保留既有身份；同 ID 的不同内容仍受用户库快照与冲突保护，不能静默覆盖。

Details 和 New board 均不出现 ID 表单，也不提供“高级设置”让用户补填。示例中的 carrier/serial-card/serial0 仅为便于说明的内部引用；实际手工新建由程序生成标识。接口、信号和模板仍填写有实际意义的名称，不额外要求一组 Name 与 ID。

## 占位符

| 类型 | 支持标记 | 工程输入 |
| --- | --- | --- |
| 主板 | `{signal name}` | 绑定的顶层信号 |
| 子卡 | `{signal name}`、`{pin name}` | 顶层信号，以及模板使用位置标记时的 FPGA 引脚 |

仅识别这两个固定标记，不开放任意正则规则、不解析约束语言、不执行 Tcl 或其他脚本。所有已知标记一次替换，插入值按字面量处理；其余花括号、引号、反斜杠及文本保持原样。标记不会递归展开。

例如 `[get_ports {{signal name}}]` 的外层花括号是用户写的 Tcl 引用，内层 `{signal name}` 是占位符；绑定后得到 `[get_ports {console_tx}]`。总线位可得到 `[get_ports {data[7]}]`。格式需要何种引用由用户模板决定，工具不自动添加 Tcl 引用或厂商转义。

主板不允许 `{pin name}`，没有物理位置输入字段。子卡含有 `{pin name}` 时，工程对应位必须填写位置；如果子卡模板直接写死位置，也无需额外位置输入。模板必须含 `{signal name}` 才能用于信号导出。编辑草稿允许暂缺，导出时检查所选模板是否完整。

每个模板是一段独立输出文本，支持多行。需要非引脚公共约束、任意条件表达式或多信号模板等能力时再另行设计；本轮不增加全局模板或规则引擎字段。

## 工程配置

继续保存于 AD 的 physical 或 RTL `.pins.json`。保留 board、可选 cards、逐位 bindings。删除 cards[].connections；逐位子卡绑定增加一个可选 pin 值。

```json
{
  "board": "user:carrier",
  "cards": [
    { "id": "serial0", "board": "user:serial-card" }
  ],
  "bindings": [
    {
      "source": { "interface": "UART0", "member": "rx" },
      "port": { "name": "console_rx" }
    },
    {
      "source": { "card": "serial0", "interface": "UART", "member": "tx" },
      "port": { "name": "sensor_tx" },
      "pin": "B7"
    }
  ]
}
```

主板必须选择，但不强制使用它某个接口；设计可只绑定子卡信号。子卡的 pin 属于工程而非板卡模型，不保存进库文件。总线各位分别保存实际 HDL bit 与需要的子卡位置。

校验限定为：模型字段及引用有效、稳定 ID 唯一、已选主板、接口方向/位宽与 HDL 匹配、实际 HDL 位存在、顶层端口/逻辑资源没有重复绑定、模板非空且含必要占位符、所选子卡位没有缺失的显式位置。用户可以保存未完成恢复草稿，正式导出必须通过上述校验。

不解析主板固定引脚，不判断电压，不维护 FPGA 封装数据库，也不检查主板与子卡跨模型的物理引脚占用，不为此显示额外警告。

## 导出

1. 主板决定本次输出后缀，所用子卡必须与其后缀一致；不同后缀不合并到一个文件，不做格式转换。
2. 取已绑定资源自己的字符串。主板只代入信号；子卡代入信号与工程填写的引脚。
3. 按稳定次序输出：主板在前、子卡按实例顺序；内部按接口、信号、位顺序。片段内部原样保留，仅在拼接处缺少分隔时补一处换行，不增加生成器正文头或厂商语句。
4. 没有绑定的资源不输出。子卡不使用主板约束、不覆盖主板属性，也没有二次引脚转换。
5. 保留现有 constraintsOutput 路径配置、输入快照、原子写入和生成归属保护，避免覆盖人工输出。

兼容性含义是“任意文本格式都能按指定标记替换并输出”，不表示工具能够验证任意 FPGA 约束语法。设计页不以此增加用户操作步骤。

## 前端：保留风格，调整任务结构

每个 VS Code 窗口只有一个 **Pin constraints** 工作台标签，顶栏切换 **Pin bindings / Board library**。导入、复制、编辑和切换工程都留在当前视图。两页草稿独立保存，互相切换不丢状态。

### 文件入口与保存

- `.v` / `.sv` 编辑器或资源管理器右键 **Add constraints**：用命令传入的文件 URI 直接进入绑定页。资源管理器目标优先于当前活动编辑器，不要求 AD、project JSON 或工程向导。
- `.ad` 工具栏/右键：用当前 AD 直接进入相同绑定页。其差异只在宿主读取顶层端口、保存配置的位置，交互布局一致。
- 顶部只显示 **Current file** 与已确定的模块，文件名称为上下文提示，不是必填选择器；后续用户切到其他编辑器时不擅自更换当前绑定目标。
- RTL 单文件只有一个模块时自动使用它；多个可用模块且命令未带模块身份时，才显示一次模块选择。模块浏览器传入精确身份时直接使用。它不是选择 AD 工程。
- 重复对同一文件操作就聚焦已存在的工作台；右键另一文件在同一个标签中切换，保留原文件绑定草稿。
- 单独从 **Manage boards** / CLI board ui 进入库时不要求先指定设计；若此时切到绑定页且没有文件上下文，显示 **Open HDL / AD file** 空状态入口。只在缺少上下文时选一次文件。
- AD 绑定保存到当前 `.ad`；RTL 默认加载已有同名 `.pins.json`，保存/导出时在需要选择路径或处理输出冲突时才询问。用户无需手写 JSON；已经选择的配置路径持续复用。约束输出沿用主板后缀。
- 所有入口使用同一工作台，不另绘一套“右键简化版 UI”。

### Board library

- 顶部 **New board / Import board**，导入只接受板卡 JSON。新建只填写名称、类型和输出后缀，内部 ID 自动生成且不显示。
- 左侧可搜索的主板/子卡列表。
- 主区 **Pins / Interfaces / Details** 三个分区，删除 Constraint source、原文导入及从约束推断的引脚索引。
- Pins 为新建后的默认分区。左侧是模板资源列表，可多选；中间是资源名与多行约束字符串编辑器。主板不出现独立物理引脚号输入框。
- 主板只显示 **Insert {signal name}**；子卡多显示 **Insert {pin name}**。右侧用少量示例值即时代入并预览，示例不是额外模型字段。
- 多选资源后 **Create interface from selection**，在 Interfaces 设置接口名、信号名、方向、位宽和有序资源列表，不重新录入模板。
- Details 只维护名称、类型和后缀，不展示 ID。保存固定在底部，复制/导出/删除放更多菜单。

### Pin bindings

- 顶部只读当前文件/模块，**Board** 必选，**Add daughtercard** 可选；不再出现 AD 工程选择、Mount、Map、Carrier pins 文案和操作。
- 子卡对话框只选模型，实例身份和显示序号自动生成，不包含引脚映射或 ID 输入。
- 左侧按主板与子卡实例显示接口；中间紧凑表格：来源信号、方向/位宽、顶层端口、FPGA pin、完成状态。
- 右侧端口列表按方向与位宽显示，并支持搜索。用户从列表拖动到中间行；拖起时兼容行高亮，不兼容行变暗，落入有效行立即绑定。方向/位宽不符或端口已被其他行使用时拒绝，保留原绑定。
- 主板行位置列为 `Fixed in template`，只需拖入顶层信号；子卡需要位置标记时才显示输入框，直接输入最终 FPGA 引脚。绑定单元格不用下拉框，已绑定时显示端口名和一键解除按钮。
- 为键盘/触控保留辅助路径：选择端口后点击目标行，或用 Tab/Enter 完成同样操作，不恢复下拉选择。
- 总线默认为一行，展开后逐位填写子卡位置并展示真实 HDL bit，不增加主板位置输入。
- 窄窗口优先保持“映射表 + 端口列表”可见；接口列表折叠为抽屉入口，模板详情可收起，拖放无需切到另一个页面。下方预览最终合并结果，底栏 **Save bindings / Export constraints**，不完整项定位到具体行。

## 共享实现与版本

共享 UI 放在已有 schematic-webview，VS Code 和 Electron 加载同一页面。core 做纯模型、信号绑定和标记替换，runtime 做用户库、文件读取与安全输出；宿主只负责命令、文档与窗口。

CLI board ui 默认打开库，pins ui 打开工程绑定，新增入口不兼容旧 XDC 命令或字段。删除约束语法解析器、XDC 等文件导入、原端口到引脚索引、旧锚点、子卡 connections 与厂商规则。

这是未发布功能。依据 AGENTS.md/changelog 直接重构 V1，不新增 V2，也不因试用包或提交日期改变 Schema。保留工作区独立 HDL 改动，不纳入本次功能。

## 验收

1. 新建主板 → 手填固定位置模板 → 组成 UART 接口 → 绑定 HDL 信号 → 导出，全程不导入或解析约束文件。
2. 主板模板中的 A1 原样保留，仅信号名变化；主板 UI 不额外要求 A1。
3. 子卡独立 LVCMOS18 模板在工程中代入 B7 和 sensor_tx；主板 LVCMOS33 不叠加，也不需要主板引脚/连接器映射。
4. 单个标签覆盖两类工作，切页、换板及重开可恢复各自草稿；键盘、搜索、明暗主题和窄窗口可用。
5. Import board 仅接受新板卡 JSON；固定标记一次性字面量替换，未知格式文本不被执行或改写；总线使用真实 HDL 位索引。
6. 缺失信号、错误方向/位宽、重复逻辑资源/顶层信号以及缺失子卡位置可定位；不增加跨板物理占用检查。
7. VS Code、CLI/Electron 共用模型与导出，保留既有文件冲突保护。
8. 从 `.v` / `.sv` 右键直接使用目标文件，既没有 AD 选择也不自动要求工程文件；单模块无需选择，多模块仅选择当前模块。
9. 浏览器真实拖放能完成绑定，方向/位宽错误不会修改既有值，支持解除及键盘两步分配；窄窗口端口列表保持可用。
10. 新建板卡/添加子卡没有 ID 表单，重命名保持内部 ID 稳定，复制产生新身份。
