# 1.5.x 第 2、3 项：HDL 模板与五列格式化方案

状态：2026-09-21 已完成实现与自动化回归，包含新增参数声明示例。

对应 [开发计划](develop_plan.md) 第 2、3 项；两项分别交付，先模板、后格式化。

## 1. 现状与范围

- `packages/flow-core/src/hdlTemplates.ts` 定义 10 个内置模板。
- `veriflow-vscode/src/testbench/templateCommands.ts` 在光标处插入模板，支持 `{{1:默认值}}`、`{{1}}` 和 `{{0}}`。HDL 的 `$display`、`$finish` 等按普通文本插入。
- `packages/hdl-runtime/src/formatter.ts` 使用 Tree-sitter 解析，格式化后重新解析并比较语法树指纹；无法安全处理时不修改文档。
- `formatterPrinter.ts` 当前按连续行中最长内容动态对齐，空行会切断对齐组；没有用户列设置。
- `hdlFormatting.ts` 的两个入口共用格式化器，但没有读取格式设置。

本次只实现 VS Code 的模板配置和显式 HDL 格式化。保留命令 ID；不修改 CLI 命令，不增加外部格式化器依赖，不自动格式化 AD/ST 导出，不改变仿真生成链路。

## 2. 用户自定义模板

### 推荐方式

在 VeriFlow 设置中增加 `veriflow.hdlTemplates` 对象，以模板 ID 为键。用户通过设置的“在 settings.json 中编辑”添加、修改、禁用模板；支持用户、工作区、工作区文件夹作用域，按当前文档读取。修改后下一次打开模板选择列表即生效。

推荐继续使用当前模板占位语法，避免把 HDL 的 `$` 系统任务解释成 snippet 变量。相比另建模板文件目录，这种方式不引入路径、文件监听和项目迁移问题；相比原生 snippet 语法，现有内置模板和 `$` 文本无需迁移。

```json
{
  "veriflow.hdlTemplates": {
    "my-register": {
      "label": "寄存器定义",
      "description": "插入可修改位宽和名称的寄存器",
      "languages": ["verilog", "systemverilog"],
      "body": [
        "reg [{{1:7}}:0] {{2:data}};",
        "{{0}}"
      ]
    },
    "clock": {
      "body": [
        "reg {{1:clk}} = 1'b0;",
        "always #{{2:5}} {{1}} = ~{{1}};"
      ]
    },
    "timeout": { "enabled": false }
  }
}
```

### 配置契约

| 字段 | 约定 |
| --- | --- |
| ID | 非空，匹配 `[A-Za-z_][A-Za-z0-9_-]*`；同名覆盖内置项，新 ID 新增项 |
| `label` | 可选，显示名称；内置项沿用原名称，新项默认使用 ID |
| `description` | 可选，选择列表的说明 |
| `body` | 字符串或字符串数组；新模板必须提供，同名内置模板可省略；数组以换行拼接 |
| `languages` | 可选，`verilog` / `systemverilog` 的非空去重数组；默认两者都支持 |
| `enabled` | 可选，默认 `true`；设为 `false` 后不出现在列表中 |

- 默认配置 `{}` 保留全部内置模板。用户不必复制整个列表。
- 设置按 VS Code 已合并的对象读取，再与内置模板逐字段合并。数组整体替换，不把模板正文逐行合并。
- 列表顺序为内置原顺序，其后新增模板按 ID 排序；覆写内置项不改变其位置。
- 删除覆盖项恢复内置内容；禁用项恢复 `enabled: true` 后重新显示。
- 保留四个旧模板子命令，读取同一份解析结果；被禁用或不适用当前语言时显示一次信息提示，不偷偷插入默认模板。
- 非法配置不阻止其他模板使用：跳过非法自定义项；非法内置覆盖回退内置值。每次调用至多汇总一条警告，列出具体配置路径，并提供打开设置操作。显式 `enabled: false` 优先，不因其他坏字段重新启用。
- 空字符串正文合法，按无操作处理；重复占位编号用于镜像。只支持现有 `{{数字:默认值}}` / `{{数字}}` 语法，不增加求值、文件包含或 shell 执行。默认值不含右花括号；其他文本原样保留。编号须为非负安全整数，超出范围的占位文本原样插入；镜像使用带花括号的内部编码，避免吸收后续数字。
- 保留单光标、只读文档、选择变化、文档版本变化保护；EOL 先统一为 LF 再转为当前文档 EOL，避免 CRLF 变成 CRCRLF。一次插入为一次撤销。
- 模板插入不触发整篇格式化；按用户正文插入，跳转占位行为沿用现有实现。

## 3. 五列格式化

### 推荐方式和设置

继续使用现有语法树打印器，增加按语法节点分类的列对齐层。默认 VS Code 格式化采用五列，保留 `adaptive` 模式用于回到旧对齐风格。不通过正则重写整份源代码，也不引入外部进程。

```json
{
  "veriflow.formatting.alignment": "columns",
  "veriflow.formatting.columns": [4, 12, 20, 44, 56]
}
```

- 列数字是从行首开始的空格偏移（从 0 计数），`4` 表示前面有 4 个空格，VS Code 显示为第 5 列。这样与原始示例的四空格缩进一致。
- 必须恰好五个严格递增整数；第一项范围 1–8，其余不超过 240。第一项同时是每级缩进空格数，不另设冲突的缩进值。
- 固定列输出使用空格。`adaptive` 保留旧动态对齐，仍按第一项控制每级缩进。
- 设置声明为文档语言可覆盖；显式命令与 Format Document 使用当前文档的同一份设置。
- 非法列设置使用整组默认值，并在当前格式化调用中只提示一次；不逐项修补出不可预测的布局。
- 核心 API 增加可选 `alignmentColumns`；未传时保持现有动态对齐，避免改变未请求此功能的 CLI/其他调用者。

### 五列的具体含义

设五列为 C1–C5。模块一级内部的默认位置分别为 4、12、20、44、56。

| 语法 | C1 | C2 | C3 | C4 | C5 |
| --- | --- | --- | --- | --- | --- |
| ANSI 端口 | `input/output/inout` | 显式类型，如 `wire/reg` | 符号属性与 packed 位宽 | 名称及 unpacked 维度 | 逗号（最后一项没有逗号） |
| 普通信号声明 | `wire/reg/logic` | 符号属性；无符号属性时放位宽 | 已有符号属性时放位宽 | 名称及 unpacked 维度 | 分号 |
| 参数声明（模块参数列表及模块内部） | `parameter/localparam` | 显式类型，如 `integer`；无类型时留空 | 符号属性与 packed 位宽 | 参数名称 | `=`，随后一个空格及初值 |
| 连续赋值 | `assign` | 左值 | 留空 | `=` 与右值 | 分号 |
| 命名参数/端口连接 | 左侧按嵌套缩进 | — | — | `(`，内容紧随其后 | `)` 及后续逗号或结束符 |
| 例化头 | 模块名 / 实例名 | — | — | `#(` 或 `(` | — |

- 缺少字段时保留语义位置，例如无显式类型的 `output [7:0] dout` 仍将位宽放到 C3、名称放到 C4。
- `signed` 和位宽同时存在时不拆分 HDL token。多维 packed/unpacked 维度保持顺序。
- 例化最后一行保留紧凑闭合形式：参数最后一项 `))`，端口最后一项 `));`，与开发计划示例一致。
- 命名连接位于例化体内时增加左侧一级缩进，但 C4/C5 跟随例化头所在层级，不能因为连接列表本身又额外右移。
- 嵌套 `generate` 等结构按外部结构深度平移整套目标列。例如例化头从 4 缩进到 8 时，其 C4/C5 从 44/56 平移到 48/60。
- 过程语句只按 C1 逐级缩进，不做五列补空格；`end else if` 保持同一行。`initial/always/generate` 按真实语法块增加缩进。
- 参数声明的逗号或分号紧随初值，不再对齐到第五列；初值可能是字符串、数字、表达式。没有显式类型或位宽时保留名称的 C4 位置，长参数名越过 C5 时在 `=` 前保留一个空格，不推动其他行。保留连续声明中省略的 `parameter` 关键字，不增删语法 token。
- 复杂用户类型、位置参数/端口和多变量信号声明不强行套入上述表；继续语法安全的普通打印。首期不扩展为完整 SystemVerilog 风格配置系统。

### 长内容和保真规则

只向右补空格，不截断、不换行拆表达式、不挪动其他行的目标列。某字段已占用目标位置时，该处放弃对齐，使用 HDL 语法所需的最小分隔；后续未被占用的目标列仍可对齐。

例如较长的右值越过 C5 后，分号直接跟在右值后；长端口名越过 C4 后，`(` 紧随名称；不会为一条长声明把整个文件的名称列推到更右。转义标识符结尾始终保留其必须的空白。

注释、字符串、宏定义及续行保持原有内容；行尾注释跟随原语句。参数声明组、变量声明组、连续赋值组之间补一空行；每个独立过程块（含 initial、always、final、generate、function、task）和每条模块例化语句之间补一空行。同组连续声明和赋值不强制逐条空行，已有空行不重复添加。格式化保留 LF/CRLF，并要求幂等。

仍执行“解析 → 打印 → 再解析 → 比较语法树指纹”的保护。存在语法错误、语法不支持或指纹改变时，不应用任何编辑并沿用现有警告。

### 例化插入和生成代码的边界

本期“例化对齐”指 Format Document 对已有例化代码的处理。`moduleInstantiationFormatter.ts` 的插入/复制输出和 AD/ST 自动生成结果暂不接入新格式设置；用户可对插入后的文档显式格式化。这样不把格式偏好带入仿真与导出依赖链。若希望“插入例化”也立即遵守五列，可作为确认方案时追加的独立交付项。

## 4. 验收与交付

1. 模板设置可新增、覆盖、禁用、恢复；不同项目设置互不串用；旧命令可继续使用。
2. `$display`、`$finish`、反斜杠、占位镜像和 CRLF 原样正确插入；取消或编辑器改变时不插入。
3. 用开发计划示例改写成合法 HDL 的 fixture 验证列位置，覆盖 `NAME`、`ADDR_WIDTH`、`CONFIG_WIDTH` 和 `localparam BAUD_RATE`；测试中修正展示示例的缺失/尾随逗号及 `if ()`，不改写原始需求示例。
4. 默认及自定义列、长内容溢出、嵌套过程/例化、数组、注释/宏、LF/CRLF、幂等、语法指纹均通过测试。
5. 两个格式化入口使用一致设置，取消和版本变化时不覆盖用户的新编辑。
6. 每项完成后分别运行相应测试，最终运行运行时和扩展完整回归；更新中英文使用说明。具体执行见 [实施计划](hdl-templates-formatting-plan.md)。

## 5. 已确认并实现的选择

- 模板通过 VS Code 设置中的 JSON 编辑，保留可覆盖的内置模板；首期不做独立图形模板管理器。
- 五列默认值为 `[4, 12, 20, 44, 56]`，从 0 计数；第一列同时控制缩进。
- VS Code 显式格式化默认启用五列，保留旧动态模式；插入模板和 AD/ST 导出不自动格式化。
- 用户于 2026-09-21 确认执行，两项已实现；119 个运行时测试、60 个扩展测试文件通过，完整示例见 `packages/hdl-runtime/test/fixtures/formatter-columns-expected.v`。
