# 模块浏览与 AD/ST 基础交互统一设计

状态：用户已于 2026-09-17 批准实施。以下最新修订优先于正文中 2026-09-16 的原始描述：

- Architecture Design 与 Simulation Task 均使用当前 AD 的 circuit-board 图标，按文件展开依赖树和实际导出文件；未生成的输出必须明确标记。
- 模块右键合并为“添加到画布”，只允许添加到当前活动标签页的 AD/ST 自定义编辑器。其他编辑器活动时禁用；命令执行再次检查，不记忆旧目标、不弹目标选择器。
- Module Browser 只有模块名和来源路径行，标题只有刷新/新建图标；移除扩展过滤弹窗、目录/文件层级和跨视图 DnD。
- AD/ST 标题均只有相同加号，空状态创建按钮样式一致。其余范围仍按精简 ST、共享 AD 交互和单 TB 生成/运行执行。


2026-09-16 为原始设计日期；执行授权与修订以上方 2026-09-17 记录为准。

本方案取代 2026-09-15 的 ST 功能规划。目标是统一交互并缩小 ST：把 1.4.5 的 Testbench 生成能力放进 AD 风格的画布，支持生成 TB 和直接运行、查看波形。不能把此前的高级功能简单藏起来，继续保留另一套产品模型。

## 1. 已核实的基础与问题

- 本地提交 `5c64c13` 的扩展版本为 1.4.5。旧 `testbenchGenerator.ts` 支持 TB 名称/输出、time unit/precision、多时钟 MHz、复位极性与持续时间、多 DUT、参数覆盖、端口信号映射、VCD 和结束时间。它没有现在的用例矩阵与 scoreboard 系统。
- 当前 `showAddInstanceDialog()` 在 ST 中转发 `addModule`，而 AD 使用 Webview 内同一个添加实例对话框。这是需要消除的行为分叉。
- 当前 ST 创建命令被放进树项，AD 用 `viewsWelcome`；标题命令图标不全，导致图标/文字混杂。
- `fileBrowserProvider.ts` 同时生成目录、文件和模块层级；新设计只显示模块定义。
- 当前过滤通过 `showInputBox()` 实现。仓库依赖的公开 TreeView API 未提供可直接嵌入自定义过滤输入的接口。本轮移除扩展过滤按钮/命令/状态；VS Code 自带树查找由宿主决定，不包装或承诺为新增过滤功能。
- 当前时钟和复位经内嵌源码编辑再添加，无法满足“预设工具节点＋右侧配置”的交互。

## 2. 方案选择

| 方案 | 代价与结果 |
|---|---|
| 仅统一文字、图标与颜色 | 保留不同对话框、第二行工具栏和复杂 ST 模型，不能解决本次问题，排除 |
| 共享 AD 的交互组件，ST 使用精简仿真模型 | 推荐；公共按钮、对话框、画布和属性表实际共用，差异仅为仿真节点、任务属性及执行动作 |
| 把 ST 完全保存成 AD，再外挂仿真配置 | 会混入 AD 的顶层端口、综合与 RTL 导出语义，增加误操作和兼容成本，排除 |

AD 文件格式及成熟交互不重写。ST 有独立文件语义，但不能复制一套相似 UI。共同操作必须走相同前端组件和公共编辑队列，宿主只负责转换文档动作。

## 3. 侧边栏

显示名称固定为 `Module Browser`、`Architecture Design`、`Simulation Task`，不加 AD/ST 括号后缀。若以后做中文本地化，三栏一起翻译，不单栏混用语言。

```text
▾ MODULE BROWSER                          ⟳  ＋
    ◇ counter          rtl/counter.v
    ◇ fifo             rtl/fifo.sv
    ◇ counter          lib/counter.v

▾ ARCHITECTURE DESIGN                         ＋
    ▸ system.ad        designs
    ▸ peripheral.ad    designs

▾ SIMULATION TASK                             ＋
      counter.st       simulations
      system.st        simulations
```

### 模块浏览

- 每行一个模块，主标题模块名，次要文字为相对源码路径。多个模块在同一文件中仍为多行，同名模块用路径区分；多根工作区的路径包含根名称。没有目录树、文件行、全局 Top 或空文件占位项。
- 点击定位到模块声明；模块右键保留“添加到 Architecture Design…”、“添加到 Simulation Task…”和复制例化。模块标识使用来源 URI 和定义身份，不能只凭模块名。
- 标题仅两个图标：刷新 `$(refresh)`、新建 HDL 文件 `$(add)`。文字只作为 tooltip/无障碍名称，不显示在标题按钮上。新建后打开普通编辑器，保存并解析出模块后才加入列表；文件操作不再伪装成模块操作。
- 删除扩展自定义过滤。本轮不改为 Webview 侧栏，不弹顶部输入框过滤。
- 从模块右键添加：有明确活动目标则加入该文档，否则使用 AD/ST 共用目标选择器；没有目标时选择新建。这个选择器只负责目标文档，不能替代画布内的添加模块对话框。

### Architecture Design 与 Simulation Task

- 两栏标题动作都只有同一尺寸的 `$(add)`，相同排序位置；不放刷新、运行、配置、选择当前任务等按钮。文件变更自动刷新，刷新命令可保留在命令面板。
- 两栏为空时都使用同一种 VS Code `viewsWelcome` 按钮：`Create Architecture Design` / `Create Simulation Task`。这是相同创建命令的空状态呈现，不生成“新建…”树行。
- 非空时只列各自文件，统一名称、路径描述、打开行为及选中状态。删除 ST 的 Current task、New task、Results、Traditional testbench、生成器等功能性根树项。
- AD 保留按文件展开依赖树及查看 RTL 的既有能力；ST 不增加不需要的结果/用例子树。统一外观不要求复制不同职责的树内容。
- 新建均只打开一次保存文件对话框，确定 `.ad` / `.st` 文件名；默认目标为所属工作区，取消不产生文件，不覆盖同名已有文件。随后打开对应图形编辑器，不再问任务名称。

### 拖放

移除本轮引入的侧栏跨视图/向编辑区添加模块的自定义拖放，明确不支持模块拖入 Webview。保留画布内部节点移动、端口连线和框选；它们属于 AD 已有画布交互，与跨编辑器拖放无关。

## 4. ST 画布：真正沿用 AD

只保留 AD 的主工具栏、中央画布、右侧属性栏和底部状态条。删除第二行 ST 工具条及 Settings/Cases/Results 抽屉。所有按钮使用 AD 的图标按钮组件、尺寸、间距、悬停/按下/禁用样式及 tooltip。

| 操作 | 统一规则 |
|---|---|
| 缩放、适应、重排、搜索、小地图、属性栏开关 | 共用 AD 现有实现、顺序和快捷键 |
| 添加模块 | 同一个 `add-instance-button`、快捷键 A、同一个画布内对话框：模块过滤、模块选择、实例名、添加/取消；不得转为顶部 Quick Pick |
| Logic Utility | 共用现有对话框、节点和属性交互；保留常量、拼接/截取等 AD 已有连线辅助能力，不引入第二套逻辑编辑器 |
| 连线、删除、选择、属性提交、撤销重做、布局保存 | 共用 AD 的交互管线；模块右键插入同样进入这套编辑动作 |
| ST 预设 | 在公共工具栏增加一个 `Simulation Utility` 图标；打开与 Logic Utility 相同结构/样式的画布内对话框，选择 Clock / Reset / Stimulus 和实例名后添加 |
| 生成 | 使用 AD 导出按钮的位置和样式，ST tooltip 为 `Generate Testbench`，输出 TB `.v`；不出现 Export RTL |
| 执行 | 同一主工具栏增加运行和波形图标；运行期间运行按钮变为停止，tooltip/可访问名称同步变化 |
| 顶层端口 | ST 的 TB 没有外部端口，不显示 Add port。其余公共按钮不另排成一套 ST 布局 |

添加普通模块和添加预设均为“选择/命名 → 添加节点 → 画布连线 → 属性栏配置”。不在添加时追问端口对应网络、时钟网络、复位网络或要求用户编辑 Verilog。只根据点击添加前的视口位置进行与 AD 相同的初始放置，不自动连接同名端口。

AD 已有的接口端口成组连线属于共用连线能力，ST 沿用同一展示和连接规则，生成时展开为实际 HDL 端口；这不包含协议事务生成或协议验证组件。

普通 HDL 模块以及已有 AD 可以作为被测模块来源。AD 在模块选择器中作为明确来源的候选项出现，保留对应端口及源码/文件来源；不创建另一条 Browse AD 向导。

## 5. 预设模块与属性栏

预设是持久化的类型与配置，生成器产生实现；不是保存在 `.st` 中的可编辑 Verilog 源码。画布上有实例名、类型和真实端口，渲染/选择/连线与普通模块一致。既不弹源码窗口，也不显示 Edit HDL/Mark ready。

| 节点 | 端口 | 右侧可配置属性与默认值 |
|---|---|---|
| Clock | `clk` 输出，1 bit | 实例名；频率 100 MHz；初始电平 0。周期作为只读换算值显示，单位遵循任务 timescale；首个翻转在半周期，不加入额外相位/占空比系统 |
| Reset | `reset` 输出，1 bit | 实例名；有效电平低；持续时间 100 个任务时间单位。仿真 0 时刻进入有效电平，到期释放；端口名不随极性改变而破坏连线 |
| Stimulus | `out` 输出，宽度可设 | 实例名；宽度 1；初始值 `1'b0`；“时间 / 值”表格。时间是从仿真开始计算的绝对时刻，遵循任务单位，默认空表表示恒定初值。支持增删行，在右栏编辑；没有 HDL/JSON 文本编辑入口 |

基础激励只做初始值和确定性时间序列，覆盖恒定、脉冲和简单数据变化。本轮没有随机、数据文件、协议、事务握手、断言、scoreboard、monitor 或任意代码。

选中对象时右栏职责：

- 普通模块：与 AD 一样显示来源、实例名、参数覆盖、端口及连接信息；端口通过画布连接，不另加 ST 专用映射表。
- Clock/Reset/Stimulus：上述类型化表单。字段使用 AD 属性编辑器的提交、错误提示与撤销方式，非法编辑不能悄悄改回默认值。
- 连接/逻辑节点：沿用 AD 属性栏。
- 点击空白处：任务属性，包括由 `.st` 文件名派生的只读 TB 模块名、时间单位、时间精度、仿真结束时间、是否生成波形和波形文件名。无弹窗设置页。

默认任务单位 `1ns`，精度 `1ps`，结束时间 `1000000`，波形开启，文件名 `<tb模块名>.vcd`。保存 `.st` 时已有空白画布，不强制生成时钟/复位节点，以保持与 AD 新建行为一致。预设添加后自动选中该节点。

基础检查：频率为正且半周期可由精度表示；复位持续时间非负；结束时间为正；激励时刻非负、严格递增，值与位宽兼容；位宽未知时保留未知并阻止需要明确位宽的编译，不猜为 1。编辑时允许未连接，运行/生成时阻止未驱动的 DUT 输入、位宽冲突和多驱动；未使用的输出给出非阻塞提示。inout 允许 0/1/x/z 激励与释放，按现有三态连接规则检查，不把 inout 简化成普通单向输出。

## 6. 生成 TB、运行和波形

ST 只表示一个 Testbench，没有用例列表。

1. 点击 Generate Testbench，检查当前图和配置，选择 `.v` 保存路径，写入可读 Verilog-2005 并打开普通文本编辑器。默认 `<st文件名>.v`；TB module 名由 ST 文件名规范化产生，改变导出文件名不再次要求命名。
2. 一个 TB 文件包含 TB 顶层和需要的预设辅助模块；模块名使用内部保留前缀并做冲突检查。若引用 AD，导出的 AD 包装也包含在 TB 文件中，实际 DUT HDL 仍作为工程依赖，不复制用户的 RTL 源码。编译时显式选择 TB 顶层，避免辅助模块被当作其他 root。
3. 点击运行，读取已保存的当前 ST 和依赖，调用同一个生成器在临时目录生成同样的 TB 和辅助模块，使用设置中选定的内部/自定义仿真器执行。不要求用户先导出，不覆盖用户已导出的 TB。
4. 自动 `$finish` 对应任务结束时间；实际进程超时和取消由运行服务管理，两者不能混为一个 UI 参数。控制台写入现有输出通道；底部仅显示未运行/运行中/完成/失败/已停止。没有验证断言时显示“完成”，不宣称 PASS。
5. 运行后波形图标打开本次输出，使用设置中内部/自定义波形器；若未开启波形或未生成文件则禁用并说明原因。没有波形列表、运行历史或结果比较。ST/依赖变化后标记上次波形已过期，不能当作新运行结果。
6. 导出和直接运行共享同一份生成输出及依赖解析。参数、连线和预设的行为不能分两条实现。导出文件可独立配合依赖 HDL 使用，不能依赖临时目录或 `.st` 内的源码。

运行前使用 VS Code 原生保存机制保存当前 ST 和实际依赖；用户取消或保存失败则停止操作。每次执行绑定明确文档 URI，不使用侧栏“当前任务”全局状态决定目标。普通编辑不需要工程写权限之外的额外确认。

## 7. 删除范围与保留边界

从 ST 产品、协议、文档模型和相应 CLI task 选项中删除：

- cases、sweeps、参数矩阵、并行队列、失败重跑、运行比较、报告/JUnit、持久化运行历史、ST 专用编译缓存；
- 自定义/内嵌 HDL、虚拟文件编辑、源码另存/引用切换、readiness；
- sequence/driver/monitor/model/scoreboard/checker/coverage/control、验证环境、事件汇总协议；
- 协议激励库、随机/文件事务源、混合模式 include/call、手写 TB 的 ST 包装模式；
- 第二行工具栏、抽屉、独立完整 TB 生成向导，以及 ST 栏内传统 TB、日志和结果树入口。

保留底层已验证的 HDL 解析、模块定位、AD 依赖与生成、通用仿真/波形器能力及编辑器“插入 HDL 模板”命令。传统手写 TB 仍可从 HDL 编辑器的既有运行命令执行，但不再属于 ST 或占用 ST 侧栏。旧完整 `Generate Testbench` 入口统一导向创建/打开 ST，不再并存两个完整生成流程。

CLI 已有 `task validate/run` 只服务精简后的单 TB；删除不再有意义的 case/jobs/compare/report 等参数，不新增长期报告系统。通用 `sim`/`wave` 与 AD 命令不随 ST 清理被误删。

ST 尚未发布：直接修订首版 schema，仓库示例和测试同步更新，无旧格式迁移、兼容适配或隐藏高级模式。旧试用 `.st` 明确报格式不支持，不能吞字段后默默改变仿真含义。

## 8. 实现边界

最小 ST 文档保存：格式/版本、任务时间与波形设置、普通 HDL/AD 实例、类型化预设实例、显式网络连接、Logic Utility 和布局。没有 `assets`、`cases`、`verification`、工具命令或工具选择。

预设配置是唯一事实来源；AD 兼容投影只负责显示，不把仿真属性写成用户 Verilog 参数字串。共用组件包括工具栏配置、添加实例对话框、Logic Utility、选择/连线、属性字段渲染、错误状态、编辑串行队列与布局持久化。不要大改无关路由算法或已完成的 AD 修复。

清理必须查实际引用，删除新 ST 独占实现和测试；共享运行底层仍被传统仿真使用时保留。遵守已有脏工作区保护和删除 fallback，不能 `git reset` 或整目录还原来获得“精简”。

## 9. 验收先看交互，再看测试

- 同一真实 VS Code 窗口并排打开 AD/ST：逐个对照相同操作的图标、位置、tooltip、快捷键、对话框、选择和属性提交。任何一个公共操作出现两种交互即不通过。
- 三栏无带文本的标题操作；模块浏览没有文件树/Top/顶部过滤框；AD/ST 空状态和新建过程一致，标题仅一个加号。
- 添加 Clock/Reset/Stimulus 全程不打开编辑器、不弹 Quick Pick 选网络；节点出现在画布，右栏可修改，连线、保存重开和撤销重做均正确。
- 验证两个不同频率时钟、两种复位极性、8 bit 激励和参数化 DUT；导出 `.v` 和直接运行波形一致；完成后能在既有波形器查看。
- 没有用例、验证环境、自定义源码、结果抽屉及拖到画布的入口或幽灵命令；AD 既有设计与 RTL 导出不退化。
- 检查深色/浅色及窄宽编辑区；主工具栏按 AD 的溢出规则处理，不回退到第二行 ST 大按钮。

确认本设计后才开始开发。此次设计文件没有表示任何新实现已经完成。
